# 作業用フォルダ案内

## このフォルダの役割

- 現在のプロジェクト方針、保守情報、将来候補、過去記録を保管する。
- ゲームが実際に読み込む設定や素材は`ゲーム本体`を正とする。
- 現行仕様は以下の現役資料、過去の経緯は`記録`とGit履歴で確認する。
- 背景・服装・表情判断のローカル移行は撤退済みで、旧試験の再実施権はない。試験結果・限界と撤去状態は臨時資料[ローカル移行試験総括・撤去記録](記録/ローカル移行試験総括・撤去記録.md)を参照する。

## 作業規則と変更作業の入口

- 共通規則と作業開始順は[ルートAGENTS](../AGENTS.md#作業開始時に読む順序)を正本とし、本書は資料の責任と案内を扱う。担当別指示は自動読込みされないため、同書の条件で選ぶ。
- 調査方法が必要な相談では[調査・計画の判断指針](担当別指示/計画・差分レビュー担当.md#調査計画の判断指針)、製品の変更では`技術仕様・保守ガイド.md`の「変更影響早見表」「対象別の読込先」から必要箇所を確認する。

開始確認の後、場面に応じて次の正本へ進む。以下は読込先の案内であり、権限・状態・検査条件は各正本に従う。

| 場面 | 読む先 |
| --- | --- |
| 変更箇所の連動先を調べる | [変更影響早見表](技術仕様・保守ガイド.md#変更影響早見表)と[依存探索・随伴範囲](技術仕様/自動検査・Git.md#計画範囲と条件付き随伴ファイル) |
| 必要な検査を選ぶ・結果を再利用する | [変更リスクと完了検査](技術仕様/自動検査・Git.md#変更リスクと完了検査)と[候補同一性](技術仕様/自動検査・Git.md#最終候補と検査結果の同一性) |
| 対象機能を何が保証しているか調べる | [自動試験の保証範囲](技術仕様/自動試験の保証範囲.md)の対象節 |
| 実装途中から再開する | [実装担当の開始前確認](担当別指示/実装担当.md#開始前確認) |
| 一貫担当で進める・閉鎖後の中断から再開する | [軽微変更の例外](担当別指示/計画・差分レビュー担当.md#軽微変更を一貫して扱う例外)・[承認後の最終化](担当別指示/計画・差分レビュー担当.md#承認後の最終化) |

## 文書更新の責任と照合先

この節は文書を追加、変更、廃止する場合だけ確認する。

- 採用済みのゲーム方針・現行機能は`プロジェクト設定.md`、正本・依存関係・API・セーブ・検査は`技術仕様・保守ガイド.md`を索引とする技術仕様書群、未実装・凍結中の案は`将来の実装候補.md`、ユーザー操作は`../ゲーム本体/ユーザー向け資料`内の該当HTMLを更新する。
- 変更に関係する本文は、名称だけでなく、対象範囲・項目数・操作手順・既定値・保持／変更する状態・例外条件を現行実装と照合する。本文と併せて、索引の「変更影響早見表」、[API経路対応表](技術仕様/自動試験の保証範囲.md#api経路対応表)、`実機確認チェックリスト.md`の項目ID・参照先を照合し、関係する追加・変更・廃止だけを反映する。
- 現役資料には現在の正解と誤修正防止に必要な短い理由だけを置く。方針変更時は現行記述を置き換え、実装だけが変わって方針、現行機能、内部契約、検査、ユーザー操作が変わらない場合は文書を更新しない。
- 文書の圧縮・統合は重複説明から行い、適用条件・例外・停止条件・権限・保護条件・必要な参照先を保つ。詳細は正本へ集約し、参照元には適用場面が分かる入口注意を残す。
- Git導入後の時系列的な変更記録はGitコミットを正本とする。`記録/Git導入前の主要変更履歴.md`へ通常の完了報告を追記せず、非自明な恒久判断は現行規則の直後へ短く記載し、詳細な経緯は必要な場合だけコミット本文へ残す。

## 現役の資料

### ルート`AGENTS.md`

- 全担当に常時必要な安全・保護規則、資料の正本関係、担当の決め方、作業内容に応じて確認する資料への導線を記録する。

### `担当別指示/計画・差分レビュー担当.md`

- 調査・計画の判断指針と、計画・独立レビュー・判定・修正要求・終了の権限を記録する。具体的な検査契約は技術仕様へ案内する。

### `担当別指示/実装担当.md`

- 計画内実装・検証・候補固定・引継ぎ・修正の責任と開始／停止条件を記録する。条件付きの技術詳細は参照先へ委ね、保証に必要な順序は残す。

### `実装計画.md`

- 計画・差分レビュー担当が、ユーザーから保存を指示された一件の計画、担当、基準Git状態、目的、範囲、完了条件、検査・レビュー基準を一時的に記録する。通常時は状態を「なし」とする。

### `進行中の作業.md`

- 役割分担を使う変更や長期作業について、現在段階、次担当、変更済みファイル、レビュー候補、検査結果、未解決指摘、未確認事項、残作業を一時的に記録する。通常時は状態を「なし」とする。

### `大規模作業計画.md`

- 独立した成果物とコミットを複数フェーズに分ける作業について、全体目標、全体条件、フェーズ境界、依存関係、現在フェーズを一時的に記録する。現在フェーズの詳細は`実装計画.md`へ記録し、通常時は状態を「なし」とする。

### `相談・事前調査.md`

- 通常相談・事前調査の判断材料を、必要な場合だけ一時的に記録する。任意利用、更新・終了の条件は同文書の「このファイルの使い方」を正本とする。採用済み仕様や実装許可の正本にはせず、通常時は状態を「なし」とする。

### `実機確認チェックリスト.md`

- PC・iPhone固有の表示や操作を、変更種類と項目IDごとに確認する。

### `AI向けサーバー操作手順.md`

- 自宅PCの保存済みキーによる屋外接続を対象に、AIによる通常利用サーバーの起動・停止・再起動・状態確認を[手順書](AI向けサーバー操作手順.md)に記録する。既存の起動処理を利用する。

### `プロジェクト設定.md`

- 共通の運用前提と利用者から見える採用済み仕様を記録する。「運用方針」から対象機能の節を選び、個別機能の詳細を毎回全読込しない。

### `技術仕様・保守ガイド.md`

- 技術仕様書群の索引として、目的、変更影響早見表、対象別の読込先、主要な保守上の注意を記録する。

### `技術仕様/実行構成・ブラウザ.md`

- サーバー、ブラウザ、共通設定、HTTP防御、画面責務の内部契約を記録する。

### `技術仕様/機能・データ契約.md`

- アドベンチャー、キャラクター、プロンプト、記憶、プレイヤー設定、セーブ、シーン画像の内部契約を記録する。

### `技術仕様/自動検査・Git.md`

- 検査入口・変更リスク・試験設計と観測・候補同一性・Gitの技術契約を記録する。担当の権限・状態遷移を再定義せず、担当文書が示す条件に応じて該当節を読む。

### `技術仕様/自動試験の保証範囲.md`

- 機能別Node試験、API経路、PowerShell・ソース契約、ブラウザ接続、型検査、設定・素材検査の保証と限界を記録する。検査の選択・実行手順は`自動検査・Git.md`を参照する。

### `将来の実装候補.md`

- 未実装または凍結中の案を記録する。ユーザー向けHTMLは、操作や表示に関係する候補だけを抜粋した案内とする。

## 過去記録

`記録`には、Git導入前の変更履歴と、完了した大規模作業の記録を保管する。

- 過去記録は現行仕様の根拠にせず、現行資料とコードだけでは分からない経緯を確認する場合に使用する。
- Git導入後の通常変更はGitコミットを正本とする。
- 各記録の内容と扱いは`記録/README.md`を参照する。
