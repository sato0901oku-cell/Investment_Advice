## このファイルの使い方

- ユーザーが保存を明示した場合だけ計画・差分レビュー担当が使う。通常は空テンプレートの「なし」、有効時は「計画あり」とし、同時に1件だけ扱う。計画保存は実装許可ではなく、開始には現在のユーザー指示と開始条件を確認する。
- 下欄に案件固有の判断・根拠と成果物を記す。担当欄には通常の役割分担か、ユーザーが認めた一貫担当かを示す。保存しない軽微変更は[担当別指示](担当別指示/計画・差分レビュー担当.md#軽微変更を一貫して扱う例外)に従い、本書を有効化しない。
- 調査・計画・判定・終了の責任は[計画担当](担当別指示/計画・差分レビュー担当.md)、実装・候補固定は[実装担当](担当別指示/実装担当.md)が所有する。一般手順を計画本文へ複製せず、必要な根拠の参照先を示す。
- 現在段階・候補・有効な検査・未解決事項・残作業は`進行中の作業.md`へ置く。会話を知らなくても判断を追えるよう、採用理由と未決事項を区別し、「前回どおり」で省略しない。
- 目的・範囲・手順・完了条件の変更は計画担当が必要なユーザー判断を得て更新する。承認と必要な確認の完了後だけ「なし」へ戻し、履歴はGitコミットへ残す。
- [条件付き随伴範囲](技術仕様/自動検査・Git.md#計画範囲と条件付き随伴ファイル)には今回許可する機械的追随の種類・境界を記す。既知パスは変更予定へ列挙し、事前調査や製品コード変更の包括許可の代用にしない。

### 目的

基本4服装を維持しつつ、人物ごとに異なる追加服装を、通常画像1枚から既存ツールで登録できるようにする。共通カタログを登録・検査・AI判定へ接続し、服装数を各所へ7件固定で書き足す改修を避ける。

### 完了条件

1. 新カタログは基本4服装を必須、追加3服装を任意として定義する。将来の任意服装はカタログへの追記で扱える。未知ID、壊れたカタログ、ラベル衝突、基本服装の欠落・任意化は明確に拒否する。
2. 登録元の基本4服装normalは必須。任意服装はフォルダなしなら未登録、フォルダがあるならnormal必須。他7表情は各服装ごとに任意。空・不正な任意フォルダを黙って未登録扱いにしない。
3. Check、Add／Update／ReplaceのApply、Node起動、設定・素材検査、正本／配信監査が同じカタログと検出済み素材集合を使う。登録済み先頭人物から服装一覧を推測しない。
4. 基本4服装だけの人物と、追加ありの人物を混在させても、所有する服装・表情だけを手動・開始設定・素材設定・AI応答・保存復元・画像参照へ渡す。
5. セーブ参照中の追加服装を削除する更新は既存の互換検査で阻止し、追加のみの更新は成立する。取消・拒否・途中失敗時の保護状態と既存のサーバー停止ガードを維持する。
6. P1では実10人物の定義・画像・既存320点・セーブ・表示値を変更しない。追加服装の実画像を要求せず、カタログにだけある未使用IDも安全に扱う。
7. 下記検査、独立レビュー、必要なPC確認を完了し、P1をローカルコミットする。

- 追加服装と基本服装の混在を扱う既存試験の拡張、fixtureの必須カタログ配置、影響選択への依存登録。
- 利用者資料・現役仕様の更新。調査根拠は[相談・事前調査](相談・事前調査.md#確認済み事実と根拠)。

- P2のPNG配置、実人物の更新BAT実行、`game-config.json`の人物項目変更、`.gitignore`の画像除外追加。
- 画像加工・生成、既存服装の削除、人物固有設定、専用UI、セーブ形式、Grok／NovelAI実API。
- 現在データの7服装化に合わせた全fixtureの一律7服装化。4服装だけの正常ケースを残す。

### 採用済み判断

- 新設`config/portrait-outfits.json`を共通定義の正本とする。形式は`{ version: 1, outfits: { <id>: { label, required } } }`。
- 初期定義は順序どおり`casual/通常/true`、`dress/ドレス/true`、`lingerie/下着/true`、`naked/裸/true`、`cheerleader/チアガール/false`、`bunny/バニースーツ/false`、`sailor/セーラー服/false`。
- 基本4のID・ラベル・必須区分を固定し、それ以外は任意のみ。IDは既存服装IDの規則、ラベルは空白除去後1～40文字・改行／禁止制御文字なし。正規化後に別IDと同じ語彙となるラベルは拒否する。定義順を登録・UIの服装順へ渡す。
- 人物`character.json`のschemaVersion 1は維持し、追加服装一覧を二重に持たせない。カタログ＋`assets/<id>`の実在を登録根拠とする。
- カタログの受理・正規化は`characters.js`の共通処理へ置く。既存`validate-character-contract.js`の入力JSONへカタログ解決用の操作を追加し、PSも同じ処理を利用する。従来の単一入力ファイル・検証呼出しと失敗応答を維持する。カタログは入口ごとに一度解決して保持し、服装・表情ごとにNodeを起動しない。
- `visual-transitions.json`の追加別名は既知のカタログIDにだけ許可する。未所有の任意服装にも別名設定を残せるが、人物の利用候補へは出さない。`チア`、`チアリーダー`、`バニー`、`バニーガール`、`セーラー`を代表別名とし、広すぎる`制服`などは追加しない。
- 全服装normal必須・共通8表情の語彙は維持。画像名のWindows相当の大小文字扱いを維持し、`normal.PNG`、`NoRmAl.PnG`の既存保証を落とさない。
- 未所有服装／未用意表情を複製・自動登録しない。既存の素材制限・応答検証・正規化を使用する。既存世界線の使用不可設定は保ち、使用不可にされていない新素材は現行の許可方式に従う。現在の見た目は自動変更しない。

### 実装手順

1. 基準・既存差分を確認。カタログ受理処理とCLI操作を追加し、正常・不正・未使用の任意定義を純粋試験で確認する。
2. Nodeの設定読込みへ必須カタログを追加。各人物の定義がカタログの部分集合で、基本4とnormalを満たし、ラベルが一致することを検証する。服装語彙はカタログから作り、人物の許可候補は実素材から作る。背景の語彙・判定は維持する。
3. 登録PSでカタログを一度解決し、各人物の画像を検出してInspectionへ保持する。定義生成・選択画像・Check・Applyへ同じ集合を渡す。任意フォルダの不正、未知の画像ID、リンク、壊れた画像を既存の保護条件に従って拒否する。未知の服装IDを黙って有効な服装へ置換しない。
4. 設定検査・人物パッケージ監査・領域03の固定4件完全一致を「基本4必須＋カタログの任意部分集合」へ変更する。カタログの任意フォルダを正本側からも走査し、定義への書出し漏れを検出する。式数やラベルの検査を単に削除しない。
5. 架空fixtureへ新必須JSONを配置し、基本4だけ／追加あり／normalだけ／任意表情混在を必要なケースで作る。実人物・実画像を試験fixtureへ流用しない。実PSのAdd／Update／Replace・削除阻止・ロールバックを確認する。
6. UIの既存動的処理、全人物共通服装欄、開始見た目、保存・AI・シーン画像参照へ新しい組合せが渡ることを既存試験へ追加する。調査時点ではブラウザ製品コードの変更は不要と判断している。
7. カタログ変更でも追加した回帰が選ばれるよう影響規則を更新する。`character-optional-expressions.test.js`を人物関連の選択へ接続し、カタログに依存する会話・保存・参照試験の選択を保証する。
8. 資料を実装済みの機能へ更新する。現在の実10人がまだ4服装であることと、追加服装が任意であることを混同しない。
9. 個別試験で反復後、候補を固定し、下記の完了検査・独立レビューへ渡す。通常サーバー・実データには追加PNGを配置しない。

### 差分レビュー重点

- グローバルな対応服装と人物の所有服装を混同して、全員に新3服装を要求／許可していないか。
- 先頭人物の服装集合を引き継ぐ処理や、4件／7件固定への置換が残っていないか。
- カタログ未使用IDの別名は受理しつつ、未所有服装を人物へ割り当てないか。
- 正本からの任意フォルダ走査がなく、定義側だけを追う監査になっていないか。
- 選択画像、更新後の候補、削除参照、取消・途中失敗の保持状態まで実際の結果を観測しているか。
- 既存ケースを削除・弱化して件数だけ整えていないか。新カタログの必須配置が全起動fixtureへ届くか。

### 文書更新

上の予定ファイルに記した現役資料・登録HTML・テンプレート案内を更新する。P1では任意追加の仕組みを現行化し、実10人の追加済み状態やGit管理外PNGの正式配置はまだ現行仕様として記載しない。P2でGit例外・実素材の復元制約・30点の同一性手順を恒久資料へ反映する。

### 注意点・停止条件

- 既存差分・権限を保護し、製品コードの予定外拡大は再計画する。検査成功のためにラベル・表情・保存・画像整合の検査を緩めない。
- 入力・セーブ・APIキー・会話本文を資料やログへ写さない。無関係な整形・分割・UI追加を混ぜない。

- P2へ自動移行しない。P1承認・コミット後に現在フェーズを切り替えて詳細計画を保存する。
