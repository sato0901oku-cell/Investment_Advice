## あらすじの限定型検査

- 入口は`ゲーム本体/node-server`での`npm run typecheck`。固定したTypeScript開発依存のローカルCLIをNode24から呼び、`tsconfig.typecheck.json`のstrict／noEmitで検査する。ネットワーク取得・生成JS・ゲーム起動時の検査は行わない。依存欠落時は失敗とし、開発依存を含む導入は同フォルダの`npm.cmd ci`を使う。
- 検査対象は`src/domain/synopsis.js`と`../public/js/synopsis.js`の@ts-check付き実コード。ブラウザはcreateController内の検証結果から文字列callbackへの受渡しまで含む。import先の`validation.js`はDataValidationErrorの型供給元であり、共有検証器全体の検査済みを意味しない。app.js配線・HTTP・保存・他のJSは静的保証の対象外。
- `typecheck/synopsis-contracts.d.ts`は規則・判別可能な結果・部品入出力、`browser-globals.d.ts`は登録先・必要な外部callbackの形を持つ。`synopsis-contract-cases.ts`は型検査専用で実行せず、正例と@ts-expect-errorの不正例で規則名・値型・正規化結果・失敗結果の誤利用を確認する。既定値と実行時検証の正本は既存JSに残す。
- `test/typecheck.test.js`は同じ設定で診断0と実JS・型ファイルの読込み範囲を確認し、コンパイラ欠落や型不整合をskipしない。npm testと標準全体検査から自動実行される。実行時の正規化・編集挙動は既存synopsis／browser-synopsis試験が担当する。
- test-impact-mapはNode／ブラウザのsynopsisとdomain/validation変更から型検査試験を選ぶ。上記tsconfigと3型ファイルは明示的なselection-infrastructureであり、基盤変更の全体fallbackを保つ。似た未登録パスはunknown-pathのまま扱う。

## 横断機能の保証

### エンディング

- エンディングの責務検査は、設定正規化・編集を`browser-adventure-configuration`／`browser-adventure-settings`、判定周回の確定値だけを使う判定（過去の成立を持ち越さない）・総括後の明示開始・連打・旧応答・再試行／省略を`browser-story-choices`、厳格入力と応答・共有再送・取消を`api-gameplay`、実HTTPモックと使用量を`gameplay-api-integration`、実ブラウザ出力の各安定状態からv27保存・再読込・同一要求再送を`persistence-integration`が担当する。3択のシステム向け文脈と場面確定後の人物経験の境界は`api-gameplay`、`browser-chat-request`、`chat-prompt`で直接観測する。実Grokの確率的描写は保証対象外。
- 背景付きエンディングの観測は`browser-story-choices`の実app登録で終了取消、A→B→Aと翌日C、無効指定背景、候補順の外見採取、通常状態不変、画像全員の一括表示・有限再試行、ロード／次周回／ホーム後の旧完了破棄を確認する。`gameplay-api-integration`は実appの採取依存→実story-flow要求builder→ローカルHTTP/Grokを通し、背景enum一件・外見、違う背景の拒否、同一JSON再試行と成功cacheを観測する。`persistence-integration`は3方式の各安定状態の実ブラウザ出力をv27 HTTP保存・再読込し、contextと通常状態の照合、不正入力拒否、固定要求の文字列一致、processed後の外見変更許可を確認する。`browser-scene-images`と実app画像配線は終了時外見の優先と文字方式の現在外見を対照し、`scene-image-api-integration`は実appのエンディング画像アダプター→実scene-images→ローカルGrok/NovelAIを通し、通常セッションを読まない固定外見、送信された背景・人物、付随JSON v5・保存再試行を観測する。これらは実端末の描画・操作保証とは区別する。

### 開始時点のあらすじ

- 開始時点のあらすじは、`synopsis.test.js`でNode／ブラウザ共通のCRLF・CR・タブ・trim・UTF-16上限・禁止制御文字・必須型を、`browser-synopsis.test.js`で下書き分離、正規化後の差分なし、取消処理／リセット／読取専用表示を直接確認する。`browser-chat-start-flow.test.js`、`browser-save-load.test.js`、`browser-save-reset.test.js`、`browser-story-choices.test.js`は通常開始・物語開始・ロード・チェックポイント・初期化の所有者と失敗巻戻しを確認し、`chat-prompt.test.js`、`api-gameplay.test.js`、`gameplay-api-integration.test.js`は空欄時の省略、非空時の開始時点引用、将来状態を断定しない境界を確認する。`persistence-integration.test.js`はv27保存と設定v4／v6の往復を実app接続で確認し、PowerShell全領域は現行キーの静的・実HTTP契約とBOMを確認する。

共通支援は2ファイルに限定する。`test-support/local-http.js`はloopbackのポート取得とOrigin・JSON/生本文送信だけを担当し、応答を消費・JSON化しない。各統合試験にJSON必須、空本文、画像bytes・Content-Typeの解釈を残す。`test-support/isolated-resources.js`は8永続パス引数、runtime停止の登録、試験単位の後始末を担当する。mode、delay、environment、外部モック、要求fixtureは個別試験の正本で、共通支援では既定値を追加しない。


`test-support/character-runtime-fixture.js`はNode機能試験の人物入力だけを定義・生成する。架空の安定ID・表示名・合法年齢・人格6項目・デモ・4服装×8表情の正本パッケージ／公開PNGと選択サムネイルを、呼出側が先に登録した一意所有rootへ作る。非人物game-config、画像／モデル設定、世界観と実プロンプト、デモ規則・視覚遷移定義を読取り継承し、素材参照は縦長の小型PNGで満たし、立ち絵と選択サムネイルは透明な四隅と不透明な内容を持つ。服装ラベルは現行の共通見た目契約に合わせる。現用人物のコピー・現用人数からの生成・保存物や依存物の再帰コピーは行わない。入力生成は上記2資源支援と別責務で、importだけでは生成・試験登録・待受け・外部通信を行わない。実製品ソースを読むgameRootと入力projectRootを分け、保存8経路は入力root内を基準とする。mode・delay・環境・要求・乱数・時計・モックは各試験が所有し、既存支援で停止をawaitしてから所有範囲だけ清掃する。再起動／別Nodeプロセスにも同じ入力・保存先を渡す。

`character-runtime-fixture.test.js`は1／2／3／5人と別ID・表示名・人格／デモ編集を実bootstrap→registry／prompt→人格API・配信設定→実会話生成→v27保存／再読込へ通す。未登録参加者の400・chat_participants_invalid、不正年齢／人格Schema／基本設定欠落・未登録profileの起動拒否、import無副作用、生成途中／起動／listen／本体失敗時の実after清掃と失敗伝播を確認する。複数人物機能は必要な3人（3非参加人物を扱うケースは4人）を明示して用意し、少人数の現用構成を理由に省略しない。

同試験は生成した1／2／3／5人の設定を実PSの非空／既定人物・全員見た目判定へ渡し、最終人物の各服装ラベル不正を拒否させる。生成設定が参照する全背景・全立ち絵の正本／公開PNG・サムネイルを実Test-ImageFileと実背景縦長分岐へ接続し、エラー／警告なしを要求する。正方形／横長背景はエラー、透過不足の立ち絵／サムネイルは警告として検出する。不透明な画素の存在は生成fixtureの補助観測であり、製品検査器が受理する完全透明PNGとの対照を含め、製品側の条件や許容警告は変更しない。

`character-definition.test.js`は現用登録全件の正式character／personality／demoと、管理処理が書き出す実行用定義・デモ・立ち絵・サムネイル、実registry・公開人格APIをIDごとに照合する。人格は実検証器の正規化結果を比較し、特定人物・表示名・人格文言・調整値を固定しない。別の架空パッケージに合法編集を与え、人格の誤割当、正本／実行用デモ不一致とregistry反映不一致を検出する。服装フォルダと表情PNGは正本集合と実行定義を双方向に比較し、通常のみの受理と正本だけに追加した任意画像の書出し漏れを確認する。起動で合法データを受理する責務と、この正本反映監査が不一致を検出する責務は区別する。`chat-demo.test.js`は架空人物の穏やかな／主体的な分岐を乱数指定・本文・人物所属・ユーザー名置換で観測する。

会話4試験、視覚遷移、解除／保存、ドメイン検証、会話／画像HTTP、同時実行／再起動と、`api-chat`・`persistence-integration`・`chat-customization-settings`・`adventure-settings`の人物機能入力は架空fixtureを使う。実ハンドラー・サービス・HTTP・ストア・ブラウザbuilder・次要求Schemaを通す既存境界を保持し、純粋な手作りmodelだけで代用しない。2人共有記憶のeventGroupId、人物別パラメーターの開始／現在／候補値、方向付き関係、人物別初期値の保存と再読込、故障／競合／取消の既存観測も維持する。ソース読取・独立した故障metadata・ブラウザ純粋入力の固定IDは現用登録依存とは区別する。PowerShell側の入力分離・可変構成の実全領域受入は後述の専用支援と手動runnerが担当し、Node fixture合格だけで代用しない。

### 設定・素材検査の責務と実行順

`validate-project.ps1`は設定・素材だけでなく、`data/custom-worlds.json`と内部予備、`data/saves`のセーブ本体・内部予備・サムネイル、`data/generated-scenes`の付随JSON・削除記録・サムネイルも読む。ユーザーデータ検査だけを除外する引数はないため、ユーザーデータを対象外とする作業では現用コピーへそのまま実行しない。

人物定義のNode検証への受渡しでは、`validation-support.ps1::Invoke-NodeCharacterContractValidation()`が人物定義・人格・ルールをOS一時フォルダの一意なJSONへ書き、`finally`で削除する。通常終了時は削除するが、プロセス強制終了・OS停止後の残存は防がない。この一時書込みを含むため、読取り専用の検査とは実行用設定・素材・セーブを自動変更しない意味であり、ファイルを一切作成しない保証ではない。

`validate-project.ps1`は引数なしの正規入口であり、`ProjectRoot`、各正本パス、`Errors`、`Warnings`、画像・音声件数、`ReferencedAssetPaths`を初期化する。入口は`tests/validation`の全ファイルについて存在・PowerShell構文・UTF-8 BOMを実行前に確認した後、次表の順に同じスクリプトスコープへdot-sourceする。分離先は`ProjectRoot`を`PSScriptRoot`から再計算せず、表記した共有値だけを参照・更新する。

| 順序 | ファイル | 責務と共有状態 |
| --- | --- | --- |
| 1 | `validation-support.ps1` | JSON、安全な相対パス、構文、画像、ハッシュ、Node委譲などの共通関数だけを定義。検査全体や`exit`は実行しない |
| 2 | `character-tools.ps1` | キャラクター登録・解除入口の存在を確認し、`Errors`を更新 |
| 3 | `image-runtime.ps1` | Windows標準画像機能を準備し、失敗時は`Errors`を更新 |
| 4 | `files-and-documents.ps1` | 必須ファイルと全ユーザー向けHTMLの相対リンクを確認し、`Errors`を更新 |
| 5 | `runtime.ps1` | PowerShell／Node.js、sharp固定版、全Node構文、アルバム保存状態、既存PS1のBOMを確認。`Errors`／`Warnings`を更新し`nodeCommand`を後続へ渡す |
| 6 | `browser-and-prompts.ps1` | ブラウザ構造・読込順・分離契約とプロンプトを確認し、プロンプト読取値を後続へ渡す |
| 7 | `configuration-assets.ps1` | JSON設定、世界観、孤立セーブサムネイル、画像・音声、人物表示を確認。`Errors`／`Warnings`、件数、参照素材集合と設定値を更新 |
| 8 | `character-packages.ps1` | 実行設定と登録済み／解除済み人物パッケージ、人格・デモの整合を確認 |
| 9 | `asset-references.ps1` | `ReferencedAssetPaths`と実素材を照合し、未参照素材を`Warnings`へ追加 |

入口は最後に対象件数、順序付き警告・エラーを一度だけ出力し、エラーなしを0、エラーありを1で終了する。Node構文違反など従来から子コマンドのネイティブエラーで即時終了する経路は集約終了へ変更しない。`runtime.ps1`の全JavaScript構文確認は`node-server/scripts/check-js-syntax.js`へ1回委譲し、`src`・`scripts`・`test`の現行`*.js`をNode.js 24の`node --check`で同時最大4件検査して全子プロセスを回収する。Node試験ランナーの固定並列数は2のままとする。Node.js 24系、依存固定版とsharpの実読込み、Node.js必須ファイル、全JavaScript構文、設定・素材、全ユーザー向けHTMLと相対リンク、孤立セーブサムネイル、アルバム正本の片割れ・破損・孤立サムネイルを、旧サーバーモジュールなしで読み取り専用検査する。

恒久回帰は`node-server/test/project-validation.test.js`から実入口をWindows PowerShell 5.1の子プロセスで起動する。警告なし正常、現用人数から独立して合成した有効な1人・2人構成とその画像件数、警告だけの非破壊、JSON不正、Node構文の即時終了、異なる責務を跨ぐ複合不正の診断順、分離ファイルの欠損・BOM・構文違反、プロジェクト外CWD、BAT・人物管理からの入口接続を固定assertで確認する。対象件数の期待値は検査出力ではなくfixtureへ与えた設定・素材構成から算出する。fixtureは`data/test-runs/p09-01-*`へ作り、カスタム世界観の正副JSONと保存用フォルダは合成し、現用の保存データをコピーしない。変更対象はfixture内のコピーだけとし、共有するNode実装・依存は読取り専用junctionに限定して終了時に削除する。恒久保証は前記assertの観測点を正本とする。Node.js固有の単体・同時実行・保存契約試験は`ゲーム本体/node-server`で`npm test`、同じ全領域試験は`npm run test:blackbox`または`test-game.ps1 -Area all`で実行する。
- JavaScriptの関数内処理を静的確認する場合は、結合済み全ソースへ無制限の`[\s\S]*?`を適用せず、`Get-TestJavaScriptFunctionSource`または開始・終了を限定した`Get-TestJavaScriptSegment`で対象範囲を切り出す。後続関数の同名処理による見逃しを防ぐためである。

CSSの読込順異常は実入口で拒否させ、CSSファイル欠落と空本文はfixture専用runnerから実検査関数を呼んで診断と他ファイルの不変を確認する。検査規則は試験側へ複製しない。
